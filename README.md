# Визитка Виталия

Небольшой GraphQL API: профиль, навыки, опыт и проекты. TypeScript, Node.js 22, NestJS 12, Prisma 7, PostgreSQL 17. Для запросов — Apollo Sandbox.

## Запуск

Нужен Docker Compose v2. Из корня проекта:

```sh
docker compose up --build -d
```

Открыть http://localhost:3000/graphql. Проверка готовности: http://localhost:3000/health.

При первом запуске создаётся база, применяются миграции и выполняется seed. API запускается только после успешной подготовки данных. База сохраняется в Docker volume. Остановить стенд: `docker compose stop`.

```graphql
query {
  profile {
    name
    description
    links { name url }
    skills { name }
    experience { company position period achievements }
    projects { name description url }
  }
}
```

## Данные

Редактируются в `data/profile.ts`. После изменения выполнить команду запуска с `--build` ещё раз. Seed обновляет записи по устойчивым ключам, сохраняет их ID и удаляет исчезнувшие из файла элементы только у этого профиля. Все изменения проходят в одной транзакции.

Виталий, fullstack-разработчик и AI-дебаггер, три года фриланса. Проекты — собственное API и Android-ферма для тестирования. Доступ к ним — по запросу: в API `url: null`, пояснение в `description`. GitHub указан в ссылках профиля.

## Почему так

- Резолвер описывает GraphQL API, сервис отвечает за получение публичного профиля, репозиторий содержит Prisma-запрос. Один `PrismaClient` на процесс, соединения закрываются при остановке. Транспорт не работает с БД напрямую.
- [Code first](https://docs.nestjs.com/graphql/quick-start): схема GraphQL собирается из TypeScript-классов в памяти. Отдельный SDL-файл вручную поддерживать не нужно. Prisma-модели остаются внутри слоя данных; служебные поля не попадают в API.
- Связи загружаются через Prisma `include`: один вызов клиента, **5 SQL SELECT**, независимо от числа навыков и проектов. Вложенные резолверы не делают запрос на каждый элемент. Сервис живёт в рамках HTTP-запроса и повторно использует загрузку при aliases. Между запросами кеша нет.
- Для одной небольшой визитки это проще DataLoader и разбора GraphQL AST. Компромисс: даже запрос только имени загрузит связи. Для большого каталога профилей потребовалась бы выборочная загрузка и batching. [Варианты загрузки связей в Prisma](https://www.prisma.io/docs/orm/v7/prisma-client/queries/relation-queries).
- Схема нормализована: профиль и четыре связанные таблицы. Составные уникальные индексы защищают от дублей и начинаются с внешнего ключа. У элементов есть явный порядок отображения.
- Миграции и seed вынесены в короткоживущий контейнер `init`. Runtime содержит скомпилированный код и production-зависимости, работает без root с файловой системой read-only. Redis, очередь и CRUD здесь не нужны: API только для чтения.

## Локальная разработка и тесты

Нужны Node.js 22.12+ и Docker. Для запуска API без контейнера:

```sh
cp .env.example .env
docker compose -f compose.yaml -f compose.dev.yaml up -d db
npm ci
npm run build
npm run db:migrate
npm run db:seed
npm start
```

Модульные тесты: `npm test` — 4 теста. Они работают без базы.

Интеграционные: задать `TEST_DATABASE_URL=postgresql://profile:profile_local@localhost:15433/profile`, затем `npm run test:integration` — 10 тестов. В PowerShell переменная задаётся через `$env:TEST_DATABASE_URL='...'`, в bash — `export TEST_DATABASE_URL='...'`.

Интеграционные тесты используют настоящий PostgreSQL и HTTP GraphQL. Для каждого запуска создаётся отдельная случайная схема, после проверки удаляется только она. Проверяются миграции с нуля, повторный и конкурентный seed, откат ошибки, сохранение ID, Sandbox и число SQL-запросов при 50 навыках. Зафиксированные версии зависимостей — в `package-lock.json`.

Оба набора тестов прошли: 4/4 и 10/10. `npm exec --yes --package=npm@12.2.1 -- npm audit --omit=dev --audit-level=high` — 0 известных уязвимостей production-зависимостей.

`docker compose up -d --no-build --wait` после сборки проверен на пустой базе: миграция и seed завершились, `/health`, GraphQL-запрос и HTML Sandbox вернули 200. Повторный запуск обновил данные без дублей, ID профиля сохранился. Отображение Sandbox в браузере здесь не проверялось: браузерная автоматизация недоступна.

## Границы

Compose предназначен для локальной проверки: пароль БД демонстрационный, API доступен только на localhost. Внешняя публикация требует отдельных секретов и HTTPS. Sandbox и introspection включены намеренно по ТЗ; для загрузки интерфейса Sandbox нужен интернет. Сам GraphQL API работает локально. Авторизация и изменение данных через API не предусмотрены.
